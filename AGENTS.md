# Project conventions

- Do not increment the userscript `@version` for every small edit.
- Keep the version unchanged during an iteration batch. Increment it only for a coherent release or when the user explicitly requests a release.
- Use semantic versioning for releases: patch for fixes, minor for new backward-compatible features, and major for breaking changes.

# Interface conventions

- Use restrained, consistent typography throughout the interface. Text at the same hierarchy level must share its font family, size, weight, line height, and letter spacing.
- Use Georgia, `"Songti SC"`, `"STSong"`, and `serif` for primary page headings.
- Use `"Songti SC"`, `"STSong"`, `"SimSun"`, and `serif` for the linked project title on the About page while retaining the primary heading size, weight, line height, and letter spacing.
- Use bold text for all four primary settings navigation options.
- Keep support links in a vertical stack ordered with GitHub first and Buy Me a Coffee second, matching the final onboarding step.

# Documentation conventions

- Keep `README.md` bilingual with the complete Chinese documentation first and the complete English documentation second.
- Describe product behavior objectively. Do not include implementation-process notes, self-referential commentary, or instructions addressed to maintainers or agents.
- Keep installation, usage, privacy, limitations, support, and license information current with the userscript.
